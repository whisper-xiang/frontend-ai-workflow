# 技术栈发现与开发规则

## 项目发现

- 先定位用户指定项目，读取适用的 AGENTS.md、工具项目规则及相关 README；这些文件不存在时仍可执行，不要求生成。
- 读取 package.json、锁文件、工作区及相关构建配置，确定包管理器、运行时、框架版本、语言和目标包。monorepo 核对工作区依赖与命令运行目录，不默认根目录就是应用。
- 确认 CSR、SSR/SSG、WebView、小程序或其他运行形态；检查路由、状态、请求层、组件库、样式与设计变量。仅检索本次有关部分。
- 命令以当前 scripts、配置和 CI 为依据；test 可能是开发服务，build 可能写入产物，不根据名称猜用途。保留现有本地产物改动。

## 按实际技术栈实施

| 类型 | 核对重点 |
| --- | --- |
| React / Next 等 | 已有组件及 hooks 风格、副作用清理、服务端与客户端边界、路由和数据获取约定 |
| Vue / Nuxt 等 | Vue 版本、Options/Composition API、SFC 与模板类型检查、响应式边界、生成类型 |
| Angular | 项目版本及 standalone/NgModule 约定、依赖注入、变更检测、订阅清理及模板检查 |
| Svelte / SvelteKit | 项目版本及现有响应式语法、服务端加载与客户端边界、路由和适配器 |
| 原生 Web / Web Components | 模块与打包方式、自定义元素生命周期、事件及 DOM 清理、浏览器支持范围 |
| 跨端 / WebView / 微前端 | 宿主协议、平台 API、资源加载、挂载卸载及共享依赖边界 |

表中是发现提示，不强制采用某框架 API；其他技术栈遵循同样方法。JavaScript 项目不强制迁移 TypeScript，旧框架不顺手升级，CSS、预处理器、CSS Modules、工具类及 CSS-in-JS 沿用项目选择。前后端混合项目只扩展到本次必要边界。

## 通用约束

- 优先复用已核实的组件、请求封装、状态、工具和样式变量。公共接口变更检查实际调用方。
- 协议以有效材料为准，不猜字段、伪造成功或绕过鉴权、错误处理及用户内容净化；敏感内容不写日志。
- 异步逻辑处理相关清理、重复操作和过期结果，行为沿用明确需求或有效约定。
- 只改本次范围与必要关联代码，保留无关未提交改动，不批量格式化或重构。
- 不用关闭检查、无依据类型断言或忽略异常掩盖问题。新增依赖先核对复用能力和项目策略并说明必要性。
- 可使用已安装且适用的专项技能，但不是前置依赖；缺失时按项目规则继续，不自动下载安装，不声称已使用。不允许专项偏好强制迁移项目。
- 类型检查匹配项目：例如普通 tsc 不代替 Vue SFC 模板检查；构建、类型和业务测试分别确认，不将一种通过当作其他通过。

# 统一交付标准

适用于需求实现、缺陷修复、样式和 mock 改动。只整理文档时执行保存回读与内容核对，不运行代码检查。跳过需求或 TODO 不等于跳过验证。

## 实现与范围

- 按本次明确要求和有效项目规则实现，优先复用组件、请求层、状态管理及样式变量，不顺手重构无关代码。
- 新增或调整异步逻辑时检查相关订阅、计时器和请求的清理，避免重复触发、卸载后更新及旧结果覆盖新状态。
- 不将检查提示变成新增业务要求。加载、空数据、失败或权限不足等行为沿用有效需求和项目约定；影响验收且未明确的决定应询问。

## 按改动选择验证

| 改动 | 相关验证 |
| --- | --- |
| 页面、表单、交互 | 主路径及受影响的加载、空数据、失败、重复操作和状态恢复；涉及键盘操作时检查焦点与可操作性 |
| 样式或布局 | 查看实际页面和受影响尺寸，检查溢出、遮挡及交互；无需为每次修改建立截图流程 |
| 接口或宿主桥接 | 参数、返回结构、错误与超时、消息关联；本地模拟和真实联调分别说明 |
| 公共组件或接口 | 核对受影响调用方和兼容性，执行相关已有测试 |
| 工具函数或状态逻辑 | 使用适用的已有测试或最小调用验证；需要防止回归的复杂逻辑补充有意义测试，不为低影响修改机械建测试 |
| 构建与资源加载 | 验证受影响构建模式及产物；宿主运行限制以项目规则为准 |

运行本次适用的已有 lint、类型检查、测试或构建命令。检查通过后不无故重复或扩大测试；纯文档修改不跑业务构建。不存在的命令不编造，也不为过关而新建检查体系。浏览器或宿主环境不可用时，说明未验证的具体行为，不能宣称已验证。

检查结果区分：通过、失败、未执行。报错涉及本次要求时先修复；无关既有错误说明具体影响，不扩大范围。环境失败与缺少命令分开说明。mock 通过不代表真实宿主或服务端联调通过。

## 完成与任务状态

状态只在规划规则选定的唯一载体维护。未获外部平台更新授权时提供核实结果，不声称状态已同步。多人任务仅修改本次授权范围，不能凭其他人的勾选或口头描述断言集成已验证。

- 满足条目完成条件且其适用检查通过后，立即勾选该条，再继续下一条，不等全部完成后批量勾选。
- 没有自动检查命令时，以与改动相称的实际操作、最小调用或代码核对确认可观察结果，并说明验证方式；不能只凭代码已写出就勾选。
- 已有必要检查因环境无法执行时，不当作命令缺失来绕过；未满足完成条件、仅部分完成或仍欠必需真实联调的条目保持未完成。
- 按任务门槛未建立持久任务的改动不为勾选而补建任务。文档记录及显式例外遵守共用工作流规则。
- 保存后检查最终差异，保留用户无关改动；需要同步的需求和任务反映当前结果。

- 跨包交付分别说明本地实现和集成状态；集成任务未满足时保持未完成，不将所有本地任务完成等同于整体完成。

## 回复

简述实际变化、验证结果，以及必要的剩余问题。提供本次实际更新的需求、任务文件路径或已有任务链接，不声称完成未验证事项。简单任务可用一小段；有多个检查或阻碍时分条说明，不要求另建交付报告、证据台账或审批环节。

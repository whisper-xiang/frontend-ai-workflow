# req-change：同步需求变化

按“更新需求 → 更新 TODO → 授权范围内编码 → 检查与勾选”处理变化，复用 req-init、req-todo 的规则，不维护第二套整理或拆解流程。

## 1. 确定本次范围

- 读取开发者最新描述，沿用已有明确授权。修改、修复、移除功能的实现请求继续做到实现；仅同步文档的请求按限定范围停止。
- 指定路径优先，否则沿用当前对话中的对应需求与 TODO，再按项目约定定位。先读取内容确认归属；多个合理候选无法判断时询问，不任选或重复新建。
- 已有功能缺少需求文档时，根据明确要求和必要的相关实现整理当前有效需求，不虚构历史要求或完成记录。
- 开发者明确的变化直接落实。只有 AI 方案需要额外改变业务行为、验收或任务边界且尚无决定时才询问，不为同一决定重复确认。

## 2. 顺序同步

1. 读取 [req-init](../req-init/SKILL.md)，执行其输入、定位、合并和核对步骤。调用范围限定为需求整理，完成后返回本流程，由本流程决定下一步，不让它自行转入 req-todo。
2. 若仅要求整理需求，返回需求路径和变化后停止。否则读取 [req-todo](../req-todo/SKILL.md)，完成检索及 TODO 更新，限定为拆解阶段，完成后返回本流程。
3. 若仅要求同步需求与 TODO 或拆任务，返回文档路径和变化后停止。已要求实现时直接执行本次更新涉及的任务，并遵循 req-todo 的“编码与完成规则”，不再次请求批准。

通过可用的 skill 调用机制执行，或读取上述同级文件并按其规则执行；不要求创建子代理或后台任务。依赖 skill 文件缺失时，说明具体缺失，优先按项目已有规则完成相应阶段，不声称调用成功；没有可用规则时执行最小的需求合并和可验证任务拆解，不自动安装依赖。

## 3. 变化处理要点

- **修改或修复**：替换冲突的旧需求及验收，保留有效内容；需要重新实现的已完成任务恢复未勾选，不清空其他任务的完成状态。
- **移除功能**：同步移除不再适用的需求和验收；旧任务删除或改为普通删除线文本。需要代码清理时新增未开始的移除任务，检查入口、相关逻辑与调用方，避免删掉仍被其他功能使用的公共能力。
- **重复请求**：读取已保存文档和必要的实现，只处理尚未满足的差异，不重复追加任务或反复重置已满足最新要求的条目。
- **局部阻碍**：输入不可读、业务决定缺失或执行失败时，说明具体问题，不推进依赖该问题的工作；继续其他已授权部分，不把局部结果说成整体完成。

不按每次变化创建新需求文件、CHG、变更编号、审批状态或交接台账。交接仅使用需求路径、TODO 路径、本次范围与必要未解决问题。

## 4. 结束与回复

仅同步文档时，对应文档保存并核对后结束。要求实现时，需求、TODO 与相关实现反映最新要求，且检查已按共用完成规则处理后结束；满足条件的条目勾选，未完成项保持未勾选。

特别遵守：缺少检查命令时，功能满足即立即勾选，如实说明未执行的检查；不要把已有命令的环境执行失败混同为命令缺失。

简述需求及任务变化、实际实现、检查结果与必要未解决问题，给出相关文档路径。不递归调用自身，不因还有其他 TODO 而扩大本次范围。
